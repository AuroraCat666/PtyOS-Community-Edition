# PtyOS 社区版 服务端

基于 .NET 8 的社区服务器，为 PtyOS 社区版客户端提供两套彼此独立、互不依赖的服务：

- **HTTP 社区服务** —— 账号注册登录、个人资料、公告、管理后台、谱面分发
- **TCP 联机服务** —— 房间、对战、聊天、实时分数同步

客户端只通过服务器地址连接它，服务端不依赖客户端。

---

## 一、功能

### 账号与社区
- 网页注册：QQ 邮箱验证码校验；用户名仅允许 ASCII 字母数字与 `_`、`-`（禁止中文与特殊字符）
- 登录 / 登出 / 找回密码 / 修改头像（头像以二进制上传）
- 密码使用 **PBKDF2 加盐哈希** 存储，不保存明文
- 游戏客户端登录与社区网页登录**共用同一份账号**，不允许随意输入未注册账号登录
- 双令牌分离：HTTP 的 `verifyToken` 与 TCP 的 `loginToken` 相互独立，登录成功后服务端轮换 token，客户端需持久化最新值

### 公告与邮件
- 发布公告，并**异步群发 HTML 邮件**给已绑定邮箱的用户
- 注册验证码 / 找回密码验证码有效期 **5 分钟**，同一邮箱有发送冷却限制，验证失败次数超限会重置
- 邮件时间统一按北京时间渲染

### 管理后台
- 用户管理：查看列表、手动创建、封禁 / 解封、删除
- 房间快照查询
- 公告发布（类型：`maintenance` / `update` / `other`）

### TCP 联机
- 房间：创建（可选是否公开）、加入、关闭、退出；仅公开房间会出现在服务器列表
- 对局：房主选曲 → 队员准备 → 房主开始游戏（服务端会校验选曲与全员准备状态）
- 实时：房间聊天、分数同步与排名
- 谱面：房主上传 zip 包，队员从服务器下载

## 二、技术栈

### 服务端
- C# / .NET 8，**不引入第三方 Web 框架**
- `HttpListener` 实现 HTTP API 与社区页面
- `TcpListener` / `TcpClient` / `NetworkStream` 实现实时联机
- `System.Text.Json` 处理通信协议与数据持久化
- MailKit + MimeKit 发送 SMTP 邮件
- PBKDF2 存储密码哈希
- Docker + Docker Compose 部署，Caddy 负责 HTTPS 反向代理
- 持久化方式为**文件型**：`data/accounts.json`、公告 JSON、头像与谱面 ZIP

### 客户端（另一仓库部分）
- Unity 6000.5.8f1 / C#、UGUI、UniTask、Newtonsoft.Json
- YamlDotNet 解析 `info.yml`，CsvHelper 解析旧版 `info.csv`
- SharpZipLib 处理谱面包，原生 TCP Socket 联机

## 四、本机开发与运行

### 环境要求
- .NET 8 SDK

### 编译并启动

```bash
cd RPGR-Server
dotnet build -c Release
bin/Release/net8.0/RPGR-Server.exe --data ./data
```

Windows 下也可以直接双击 `启动服务器.bat`，它等价于上面第二条命令，并以最小化窗口启动。

启动成功的标志是看到这几行：

```
[INFO] ========= RPGR Community Server =========
[INFO] [Auth] 数据目录: ...\data
[INFO] [Config] HTTP=127.0.0.1:8080  TCP=26377
[INFO] [HTTP] 社区服务已启动: http://127.0.0.1:8080
[INFO] [Mail] SMTP 未配置，邮件功能不可用
[INFO] [TCP] 联机服务已启动: 端口 26377
```

> `[HTTP]` 那行打印的是**对外地址**（由 `--public-url` 决定，会写进 `manifest.json` 供客户端发现），
> 不一定等于实际监听地址；实际监听地址看 `[Config]` 那行。

默认监听 `127.0.0.1:8080`（HTTP）与 `26377`（TCP），数据目录为当前目录下的 `data/`。

本机未配置 SMTP 时会出现 `[Mail] SMTP 未配置，邮件功能不可用` —— 这只影响验证码邮件发送，**联机与社区浏览不受影响**。

### 重置账号

用环境变量指定要保留的管理员，清空其余全部账号（危险操作，会覆盖 `data/accounts.json`）：

```bash
RPGR_ADMIN_USERNAME=admin RPGR_ADMIN_PASSWORD=你的新密码 \
  bin/Release/net8.0/RPGR-Server.exe --data ./data --reset-accounts
```

## 五、部署（Docker）

### 目录与容器约定

- 部署目录：`/opt/ptyos`
- 容器名：`rpgr-server`
- 数据目录：宿主 `./data` 挂载到容器 `/data`，重建容器不丢数据

### 环境变量

**SMTP 授权码必须通过环境变量传入，绝不要写进 Dockerfile 或提交到仓库。**

在部署目录下创建 `.env`：

```bash
SMTP_PASS=你的邮箱授权码
```

`.env` 已同时被 `.dockerignore` 和 `.gitignore` 排除，不会进入构建上下文，也不会被推送。

### 构建与启动

```bash
cd /opt/ptyos
docker-compose up -d --build --force-recreate rpgr-server
```

> 注意：构建与运行都依赖 `.env` 里的 `SMTP_PASS`。若该变量缺失，容器仍能启动，但日志不会出现 `[Mail] SMTP 已配置`，验证码邮件将无法发送。

### 端口

| 端口 | 绑定 | 用途 |
|------|------|------|
| `8080` | 容器内 | HTTP 社区页 + API |
| `18080` | 仅 `127.0.0.1` | 供 Caddy 反向代理，不对外 |
| `26377` | `0.0.0.0` | TCP 联机服务，需对外 |
| `80` / `443` | 宿主机 | Caddy，负责 HTTPS 与跳转 |

### 反向代理

HTTPS 由 Caddy 终结，反代目标是 `127.0.0.1:18080`。

本目录下的 `Caddyfile` 是一份**留存副本**，其中带 `# BEGIN PTYOS` / `# END PTYOS` 标记，便于把它整段嵌入宿主机上共用的 Caddyfile 中。

**真正生效的是 Caddy 实际加载的那份配置文件**（可能与 Caddy 自身而非本服务同目录）。修改域名、HTTPS 或访问日志时，请改真正生效的那份并 reload Caddy，改完可顺手把本副本同步过来。

## 六、配置项

### 命令行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--host` | `127.0.0.1` | HTTP 监听地址，容器内用 `*` |
| `--http` | `8080` | HTTP 端口 |
| `--tcp` | `26377` | TCP 联机端口 |
| `--data` | `./data` | 数据目录 |
| `--name` | `RPGR Community Server` | 服务器显示名 |
| `--motd` | `社区版服务器` | 服务器公告语 |
| `--public-url` | `http://127.0.0.1:8080` | 对外 HTTP 基址，写进 `manifest.json` 供客户端发现 |
| `--public-tcp-host` | `127.0.0.1` | 对外 TCP 主机名 |
| `--smtp-host` | 空 | SMTP 服务器 |
| `--smtp-port` | `0` | SMTP 端口（163 邮箱用 `465`） |
| `--smtp-user` | 空 | SMTP 用户名 |
| `--smtp-pass` | 空 | SMTP 授权码，**从环境变量注入** |
| `--smtp-from` | 空 | 发件人地址 |
| `--reset-accounts` | — | 清空账号，仅保留环境变量指定的管理员 |

### 环境变量

| 变量 | 用途 |
|------|------|
| `SMTP_PASS` | SMTP 授权码，经 `docker-compose.yml` 注入容器 |
| `RPGR_ADMIN_USERNAME` | 配合 `--reset-accounts`，重置后保留的管理员用户名 |
| `RPGR_ADMIN_PASSWORD` | 同上，管理员密码（8–128 位） |

## 八、API 一览

### 基础与游戏认证

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api` | 服务状态、认证模式、API 版本 |
| GET | `/api/manifest.json` | 客户端服务器发现配置 |
| GET | `/api/userlogin?username=&password=` | 游戏客户端登录，返回 `verifyToken` |
| GET | `/api/userverify?username=&verifytoken=` | 校验 token，成功后轮换并返回新 token |

账号必须已通过社区注册或由管理员创建，**不会自动创建未知账号**。

### 社区账号与会话

| 方法 | 路径 | 请求体 |
|------|------|--------|
| POST | `/api/community/send-code` | `{"email":"xxx@qq.com"}` 发送注册验证码 |
| POST | `/api/community/register` | `{"username","password","email","code"}` |
| POST | `/api/community/login` | `{"username","password"}`，写入会话 Cookie |
| POST | `/api/community/logout` | 清除会话 |
| GET | `/api/community/me` | 当前登录状态与公开资料 |
| POST | `/api/community/forgot-password` | `{"email"}` 发送找回验证码 |
| POST | `/api/community/reset-password` | `{"email","code","newPassword"}` |
| POST | `/api/community/avatar` | 上传头像二进制，需登录 Cookie |

注册约束：用户名 3–24 位（字母 / 数字 / `_` / `-`），密码 8–128 位，**邮箱仅支持 `@qq.com`**。

### 社区公开接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/community/status` | 服务器名、公告、房间快照、成员数 `memberCount` |
| GET | `/api/community/announcements` | 公告列表 |
| GET | `/avatars/{filename}` | 用户头像 |
| GET | `/assets/app.css`、`/assets/app.js` | 社区前端静态资源 |

### 管理员接口

以下接口均需有效的社区 Cookie，且账号 `isAdmin = true`。

| 方法 | 路径 | 请求体 |
|------|------|--------|
| GET | `/api/community/admin/users` | 全部账号 |
| GET | `/api/community/admin/rooms` | 房间管理快照 |
| POST | `/api/community/admin/ban` | `{"username","banned"}` |
| POST | `/api/community/admin/delete` | `{"username"}` |
| POST | `/api/community/admin/create-user` | `{"username","password","email"}` |
| POST | `/api/community/admin/announcements` | `{"type","title","content"}` |

### 谱面接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/upload` | `multipart/form-data`，字段名 `file`，上传 zip 谱面包 |
| GET | `/api/download?chartid={id}` | 下载指定谱面压缩包 |

上传会校验 multipart 边界与 ZIP 文件头 / EOCD，损坏的谱面包不会入库。

### TCP 联机协议

TCP 消息为 UTF-8 JSON 对象流。客户端请求通用格式：

```json
{
  "operate": "User_LoginToServer",
  "username": "Yuncishu",
  "verifyToken": "verifyToken",
  "addition": {}
}
```

登录后改用服务端下发的 `loginToken`：

```json
{
  "operate": "Server_Sync",
  "username": "Yuncishu",
  "loginToken": "会话 token",
  "addition": {}
}
```

主要 `operate`：

| 操作 | 说明 |
|------|------|
| `Ping` | 服务器探测 |
| `User_LoginToServer` | TCP 登录 |
| `Server_Sync` | 获取房间列表与谱面服务信息 |
| `User_CreateNewRoom` | 创建房间，`addition.IsPublic` |
| `User_JoinRoom` | 加入房间，`addition.RoomID` |
| `User_CloseRoom` / `User_QuitRoom` | 关闭房间 / 队员退出 |
| `Room_Sync` | 获取当前房间谱面信息 |
| `Room_UpdateSong` | 房主更新曲目 |
| `User_Ready` / `User_UnReady` | 队员准备状态 |
| `Room_GameStart` | 房主开始游戏 |
| `Room_SendMessage` | 聊天，`addition.Message` |
| `Game_ScoreSync` | 实时分数同步，`addition.Score` |
| `User_GameEnd` | 上报游戏结束 |
| `User_LeaveServer` | 离开 TCP 服务 |

服务端主动推送使用另一种包结构：

```json
{
  "Type": "Active",
  "operate": "UpdateScore",
  "from": "Yuncishu",
  "Score": "456789"
}
```

常见主动操作：`Message`、`GameStart`、`RoomClosed`、`UpdateSong`、`UpdateScore`、`PlayerQuit`。

## 九、数据与安全

- `data/` 下的 `accounts.json` 含账号、密码哈希与邮箱，属于**用户隐私数据**，已被 `.gitignore` 排除，**任何情况下都不要提交或上传**
- 头像与谱面 ZIP 同样位于 `data/`，体积可能较大，勿入库
- 仓库中的 `Dockerfile` **不含任何真实凭据**，SMTP 授权码一律走环境变量
- 部署机上 `.env` 建议设置为仅属主可读：`chmod 600 .env`
- 定期备份 `data/`，账号数据为文件型存储，丢失即无法找回

## 十、常见问题

**客户端提示"无法连接服务器"**
依次确认：`26377` 是否对外可达、`/api` 是否返回 JSON、Caddy 是否正常反代到 `127.0.0.1:18080`。

**收不到验证码邮件**
检查 `.env` 中的 `SMTP_PASS` 是否存在、容器日志是否有 `[Mail] SMTP 已配置`、发件邮箱是否为 163 且已开启 SMTP 服务。若提示"仅支持 QQ 邮箱"，是注册邮箱规则限制，与 SMTP 配置无关。

**验证码提示已过期**
有效期为 5 分钟，且同一邮箱有发送冷却限制，需等待冷却结束再试。

**重建容器后数据丢了**
说明 `data/` 没有正确挂载。确认 `docker-compose.yml` 中的 `./data:/data` 仍在，且是在部署目录下执行命令。

**改完配置没生效**
`docker-compose up -d --build` 才会重新构建镜像；仅 `restart` 只重启容器、不复用新代码。
